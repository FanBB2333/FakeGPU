FakeGPU

Validate CUDA-facing applications, estimate GPU memory, and simulate distributed GPU workflows without a production GPU cluster.

FakeGPU makes a machine without a GPU look like it has one. Applications see configurable NVIDIA-like devices, while the supported operations actually run on the CPU. Along the way, FakeGPU records memory use and communication, so you can check whether code works and whether a workload would fit before you pay for real hardware.

examples

Run PyTorch code on FakeCUDA. Initialize FakeGPU before importing PyTorch.

import fakegpu

fakegpu.init(runtime="fakecuda", profile="a100", device_count=2)

import torch

device = torch.device("cuda:0")
model = torch.nn.Linear(8, 4).to(device)
loss = model(torch.randn(2, 8, device=device)).square().mean()
loss.backward()

print(torch.cuda.device_count())      # 2
print(torch.cuda.get_device_name(0))  # NVIDIA A100

Run an unmodified program. The launcher sets up LD_PRELOAD or DYLD_INSERT_LIBRARIES for you.

$ python3 -m fakegpu --build-dir build --devices "a100:2,h100:2" \
  python3 your_script.py

Estimate. Check memory before a run.

# Run train.py up to the forward pass and report whether it fits.
$ python3 -m fakegpu preflight --runtime fakecuda --profile a100 \
  --stage forward --report-dir build/preflight -- python3 train.py

# Estimate LLM inference memory from safetensors headers only.
$ python3 -m fakegpu estimate-llm --model-dir /models/example \
  --prompt-tokens 128 --generated-tokens 32 --target-profile a100

# Plan an online serving pool.
$ python3 -m fakegpu plan-serving --model-dir /models/example \
  --active-sequences 16 --prompt-tokens 4096 --generated-tokens 256 \
  --target-profile a100

SMI. Inspect simulated devices.

$ export FAKEGPU_SMI_STATE_DIR=build/smi
$ python3 your_script.py &
$ python3 -m fakegpu nvidia-smi --state-dir build/smi

How it works

There are three ways to use it. Pick whichever fits your code.

01

Python FakeCUDA

Lets PyTorch code use cuda devices while tensors stay on the CPU.

Entry point
fakegpu.init(runtime="fakecuda", profile="a100", device_count=2)
02

Native interception

Loads in place of the CUDA libraries, so unmodified programs can run. The launcher sets up LD_PRELOAD or DYLD_INSERT_LIBRARIES for you.

libcudalibcudartlibcublaslibnvidia-mllibnccl
Entry point
python3 -m fakegpu --build-dir build --devices "a100:2,h100:2" python3 your_script.py
03

Static estimators

Read model metadata and configs and report memory, FLOPs, and communication without loading weights.

Entry point
python3 -m fakegpu estimate-llm --model-dir /models/example --target-profile a100

You only need a real GPU for passthrough, hybrid, and calibration runs.

Quick start

Set it up and get a CUDA device on your CPU.

1

Requirements

Linux or macOS, Python 3.10+, CMake 3.14+, a C++17 compiler, and PyTorch for the Python runtime.

Linux or macOSPython 3.10+CMake 3.14+C++17 compilerPyTorch

On Debian or Ubuntu, install build-essential. On macOS, install the Xcode Command Line Tools.

2

Build and install

Clone the repository, build the native libraries, and install the Python package.

bash
git clone https://github.com/FanBB2333/FakeGPU.git
cd FakeGPU
scripts/build.sh
FAKEGPU_BUILD_DIR="$PWD/build" python3 -m pip install .
3

Check that everything works

doctor checks the profile catalog, native libraries, and PyTorch. demo runs a small training step on the CPU while the program sees a CUDA device.

bash
python3 -m fakegpu doctor --list-profiles
python3 -m fakegpu demo --profile l4
Then run your own code: see the examples above ↑ Native interception → Documentation →

Limitations

What FakeGPU can and can't do.

FakeGPU is a development, compatibility-testing, and capacity-planning tool. It does not provide numerical or performance parity for arbitrary CUDA kernels. Passthrough, hybrid, and calibration workflows still require a real CUDA stack.

  • Native simulation does not run arbitrary CUDA kernels, and FakeCUDA does not cover binary CUDA extensions.
  • Memory estimates can miss backend-private allocations, custom operators, and allocator behavior. Calibrate on real hardware before relying on them.
  • Timing results from the simulator are not NCCL, NVLink, or kernel benchmarks.
  • Hybrid and passthrough modes need a working CUDA stack.
